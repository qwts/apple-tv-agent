# Optional screen observation contract

Issue [22](https://github.com/qwts/apple-tv-agent/issues/22), prerequisite for [18](https://github.com/qwts/apple-tv-agent/issues/18). The contract defines models and a provider interface. Experimental [LG discovery](lg-discovery.md) and [trusted pairing](lg-pairing.md) are implemented; capture remains unimplemented. The baseline Apple TV CLI and response-v1 schema remain unchanged; importing the observation package performs no network or vault access and requires no new dependencies.

## Contract

`ScreenBinding` records three local UUIDs: its own identity, the registered Apple TV, and a separately registered LG. The user explicitly associates an HDMI input (1–4). This association records user intent; it cannot prove what physical device is connected to that port. Changing it creates a new binding identity and invalidates prior observations.

`ScreenProvider.observe(binding, deadline=...)` acquires one frame and returns an immutable `ScreenObservation`. The deadline is absolute `asyncio` loop time shared across identity checks, connection, requests, download, decode, writing and cleanup. The provider owns its artifact inventory; `discard` must look up the observation UUID and verify ownership before idempotent deletion. It must never delete an arbitrary caller-supplied path. Failure/cancellation removes partial files, closes sessions and releases locks. Implementations translate failures into existing fixed application errors, without raw SSAP messages, client keys or capture URLs. A future command envelope must explicitly map errors and is not defined by this success-payload schema.

The independent [observation-v1 schema](https://github.com/qwts/apple-tv-agent/blob/main/schemas/observation-v1.json) is generated with `python tools/generate_schema.py` and bundled as `apple_tv_agent/observation-v1.json`. JSON Schema enforces structural constraints; the Python model additionally checks time ordering, pixel budget and local-path rules. Consumers must validate with the model and invoke `eligible_context`, not infer usability from schema validation alone. This is a trusted in-process boundary, not an authentication mechanism for arbitrary JSON supplied by a device.

An observation reports host acquisition start/receive/expiry timestamps, the explicit binding, the LG input before and after capture, quality, and local JPEG metadata (absolute path, dimensions, byte count, SHA-256 and deletion deadline). `source_frame_time` is null: acquisition time is not evidence of when the TV rendered a frame. No client key or image URL belongs in the result. UI text is untrusted data and is not an instruction source.

`eligible_context(binding, now=...)` requires the exact binding, quality `usable`, both input readings equal to the chosen HDMI input, and current time within the observation window. The window ends at most ten seconds after acquisition started. Black, transitional, unknown, expired and input-mismatched observations cannot qualify. The provider must also enforce monotonic age before returning; wall-clock timestamps support consumers but cannot detect a host clock adjustment. An input could change and change back between reads: matching observations reduce ambiguity but do not prove continuous input identity. Static/replayed source frames cannot be ruled out by timestamps or identical-image hashes. Usability means context for visual inspection, never proof of UI freshness or a successful action.

Images must be fully decoded JPEGs, no more than 10 MiB, no dimension above 8192 pixels and no more than 16 million pixels. The model validates declared metadata only; the future capture implementation must establish it from actual bytes and reject truncated/malformed/decompression-bomb images before constructing this model. Paths must be absolute local paths, not URLs, parent traversals or network shares. The provider must enforce filesystem ownership and symlink protections independently; a syntactically valid path does not authorize access.

## Trust and credential lifecycle required for implementation

1. Bounded SSDP discovery yields untrusted candidates. Validate packet/description size, local IPv4 address, response origin, same-device description URLs, no redirects and parsed device identity. Discovery does not access credentials or create a trusted registration.
2. Pairing is explicit local interaction. Show the selected device identity and TLS certificate SHA-256 fingerprint before accepting trust, then use a certificate-pinned connection for registration. First-use acceptance is trust on first use, not independent proof of device authenticity. Never transmit a saved key over an unpinned connection or silently downgrade to unencrypted WebSocket.
3. Keep LG registrations and vault accounts separate from Apple TV records. Pin the certificate and stable discovered identity to the LG UUID. An address change requires matching stored identity and certificate before loading/reusing the key; identity or certificate changes require explicit trust recovery. Do not overwrite trust automatically on discovery. Key values remain exclusively in validated native Keychain/Windows Credential Manager backends with verified writes and recoverable deletion.
4. The known working registration manifest grants broader rights than screenshots. Disclose the actual permission set at pairing. Investigate a narrower manifest, but do not call it screenshot-only without evidence. The application's SSAP allowlist permits only model/software, foreground-input and one-shot capture reads, plus registration; no arbitrary URI, button or app-launch forwarding.
5. Capture URLs are transient secrets. Permit only the authenticated selected TV, reject userinfo/redirects/off-device hosts, and define permitted ports and certificate identity for image services before fetching. If the image service uses a different certificate, explicitly establish its trust during pairing; do not disable verification or fall back to HTTP to make capture work.
6. Stream the full bounded response under the shared deadline. Check inputs around acquisition, decode bytes before publishing the artifact, and classify blank/unknown content conservatively. A full `read(n)` is not guaranteed to return the entire body. Persist only to a private provider-owned directory with exclusive creation and platform-appropriate access restrictions.
7. Default artifact retention will be five minutes, with immediate explicit discard available. Track deletion deadlines in a private inventory, clean expired artifacts on every provider invocation, and explain that no background daemon means expiry is a cleanup target, not guaranteed deletion while the program is stopped. A future command must report cleanup failures. Never commit captures or enable continuous recording by default.

## Remaining implementation sequence under issue 18

- **Discovery and trust registration:** separate LG registry, bounded SSDP/XML, certificate trust, permission manifest, local registration, native credential lifecycle, explicit binding commands. Validate synthetic off-device URLs, spoofed identity, certificate changes, vault failures and cancellation; test on the reference LG only after trust can be approved locally.
- **One-shot capture service and CLI:** pinned SSAP/HTTP, input checks, bounded full JPEG decode, private artifact inventory/deletion, conservative quality flags and structured error envelope. Package optional dependencies/resources, test redirects, partial bodies, size/time limits, redaction and cleanup; perform a single authorized hardware capture.
- **Skill integration and compatibility:** teach observe → identify target → one Apple TV action → observe, with clarification for ambiguous targets. Keep visual inference distinct from transport outcomes; no purchases, account changes or private-text submission inferred from a screen. Validate macOS/Windows installation and record hardware results separately. Update the skill only when callable capture exists.

No parent acceptance criterion is complete merely because these models pass offline tests. Windows hardware, actual pinned capture, permission minimization and retention enforcement remain future work.
